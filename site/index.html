Getting started

Three steps from an empty page to a themed screen. No build tool needed.

1. Add the files

Hali is plain CSS, an SVG sprite and an optional script. Copy the tokens, css, icons and js folders into your project, or add the repository as a Git submodule. Load the tokens first.

View code
<!doctype html>
<html lang="en" data-theme="dark">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <meta name="color-scheme" content="dark light">
  <link rel="stylesheet" href="tokens/hali-tokens.css">
  <link rel="stylesheet" href="css/hali.css">
</head>
<body>
  <!-- Paste icons/hali-icons.svg here once, then use icons with <use href="#i-search"/> -->
  <main class="h-page">
    <h1 class="h-page-header__title">Hello, Hali</h1>
    <button class="h-button h-button--bold">Create project</button>
  </main>
  <script src="js/hali.js" defer></script>
</body>
</html>

2. Choose a theme

Dark is the default. Set an attribute on the root element to choose explicitly. With no attribute Hali is dark, and it switches to light only when the system asks for it. prefers-contrast: more is honored automatically.

View code
<html data-theme="dark">                              <!-- default -->
<html data-theme="light">
<html data-theme="light" data-contrast="more">       <!-- increased contrast -->
<html>                                               <!-- dark, or light if the system asks for it -->

3. Use tokens in your own CSS

Components cover most of a screen. For everything else, use semantic tokens and never a hex value, so themes keep working.

View code
.my-panel {
  background: var(--hali-surface-raised);
  color: var(--hali-text-default);
  border: 1px solid var(--hali-border-default);
  border-radius: var(--hali-radius-lg);
  padding: var(--hali-space-16);
  box-shadow: var(--hali-shadow-raised);
}
.my-panel__hint { color: var(--hali-text-subtle); font: var(--hali-type-body-sm); }

Browser support

Current evergreen browsers: Chrome and Edge 111 or newer, Safari 16.4 or newer, Firefox 113 or newer. Hali uses cascade layers, :has(), color-mix() and CSS masks. Fonts are named in the stacks but not bundled: add Inter and JetBrains Mono, or let the system fonts through.

Principles

Five rules that settle most design questions.

1

Dark first, light supported

Design in dark. Derive light. Dark is the default theme and the one every decision is made in.

2

Readable always

7:1 for primary text, 6:1 for secondary text, never below 4.5:1 for anything readable, 3:1 for icons, borders and focus.

3

Calm density

A 14px body, a 4px grid and 36px controls. Quiet, not sparse.

4

Tone over shadow

Depth comes from tonal surface steps. Shadows are kept for things that float.

5

One source of truth

Tokens are generated, checked and shipped as JSON and CSS. Nothing hard codes a color.

Guidelines

  • Choose a role by what the text does, not how big you want it. Use title for card and section names, label for controls, and body for reading.
  • Keep line length between 45 and 75 characters. h-prose caps at 68ch.
  • Use two weights at most per view: regular and one of medium or semibold.
  • Use h-tabular for numbers that line up in columns or change in place.
  • Heading classes change how a heading looks, never what it is. Keep one h1 per page and do not skip levels.

Elevation

Tone first. Shadow only for things that float.

Hierarchy comes from tone: look at the five surface steps in the Color section. Shadows are reserved for things that float above the page and are only visible against a quiet background.

raised
Cards that need to lift
overlay
Menus and popovers
modal
Dialogs and sheets
  • A card sitting on the page is surface.raised. It needs no border and no shadow: the tone does the work. Use h-card--outlined when you need a line.
  • Menus, popovers and toasts use surface.overlay and shadow.overlay.
  • Dialogs and sheets use surface.overlay, shadow.modal and a scrim.
  • In light, shadows are tinted with the palette's own deep color so they stay soft and cool.

Data visualization

A color order that stays distinguishable and never depends on color alone.

Use the eight accent fill colors in this order. Each meets 3:1 against the page, and neighbors in the sequence differ strongly in hue and lightness.

  • Activations

  • Never encode meaning in color alone. The chart above also changes line style and marker shape per series.
  • Use six series or fewer. Past that, group, filter or small multiples.
  • Label lines directly at their ends when there is room, and keep a legend for the rest.
  • Gridlines use border.default. Axis text uses text.subtle at the label-md size.

Rules for using the system

  • Never convey meaning by color alone. Status needs an icon or a word as well. Links inside running text keep their underline.
  • Do not put raw palette colors on text. Use semantic tokens.
  • Label every control with a visible h-label, or aria-label for icon only buttons.
  • Test with a keyboard, a screen reader, 200 percent zoom, reduced motion and forced colors.

Content and voice

Plain, specific and short. Interface text is part of the design.

Voice

Clear

Say the thing. One idea per sentence, plain words, no jargon the reader has not used themselves.

Calm and warm

Hali is quiet by design, with a little warmth. No exclamation marks, no urgency theater, no jokes at the expense of a real problem. A light touch is welcome in safe moments: a success, an empty state, a first run.

Direct

Lead with what the person needs to know or do. Put the reason second.

Human

Write the way a capable colleague would talk. Use 'you' and 'we' sparingly and 'please' almost never.

Tone by situation

WarningSpecific and earlyStorage is 92% full. Free up space or upgrade before uploads stop.

Writing rules

Sentence case
Headings, buttons, labels and menu items use sentence case: 'Create project', not 'Create Project'. Proper nouns keep their capitals.
Buttons start with a verb
Name the result: 'Save changes', 'Invite people', 'Delete project'. Avoid 'OK', 'Yes' and 'Submit'.
Confirm with the same words
A dialog titled 'Delete project?' has a button that says 'Delete project'.
Errors say what happened and what to do
Use the pattern: what went wrong, why if it helps, how to fix it. 'Enter a full address, like alex@acme.com.'
Placeholders are examples, not labels
Every field has a visible label. A placeholder shows a sample value and disappears on typing.
Numbers, dates and units
Use digits. Write dates as 'Oct 17, 2026' and respect the person's locale. Put a space between number and unit: '16 MB'.
Avoid filler
Cut 'Please', 'Simply', 'Just', 'Oops' and 'Sorry' unless something truly went wrong on our side.
Be inclusive
Write about people, not about ability. Do not use idioms that do not translate. Do not rely on color words alone: 'the red button'.

Versioning

Semantic Versioning for a design language.

Hali follows Semantic Versioning, with one version for the whole system. Tokens, CSS, icons, script and docs always ship together. The public API is token names and their guarantees, class names and markup, icon ids, layout metrics and the theme attributes. Specific color values are not API: roles and contrast guarantees are.

ChangeExampleWhat qualifies
Major2.0.0Removing or renaming a token, class or icon. Changing a layout metric or required markup. Weakening a contrast guarantee. Changing the default theme.
Minor1.1.0New tokens, components, variants and icons. Deprecations. Color refinements that keep every role and every contrast check passing.
Patch1.0.1Fixing a contrast miss or a rendering bug. Documentation fixes. Nothing that adds API surface.

Deprecation

  • Announce it in the release that adds the replacement, under Deprecated.
  • Keep it working for at least one full minor release.
  • Remove it only in the next major release, under Removed.

The full policy, release checklist and changelog conventions are in docs/VERSIONING.md.

Version 3.0.0 Latest 2026-10-18

Hali stops looking like an enterprise console. Version 3 is soft where you touch and crisp where you read: pill controls, borderless cards that get their depth from tone, a halo of brand light, deeper surfaces, and two kinds of motion. It borrows structure from Atlassian, depth and state from Material 3, and layering, contrast discipline and productive and expressive motion from IBM Carbon. Roles, class names and icons are unchanged. Shape, size, type and the default palette are not, which is why this is a major release. See docs/MIGRATING-3.0.md.

Breaking

  • Default palette is Polar, not Nord. Roles and contrast guarantees hold. data-palette="nord" restores the 2.x palette.
  • **--hali-nord-* is deprecated** and fixed to stock Nord. Use --hali-palette-*, which follows the active palette. In tokens/hali-tokens.json the nord.* keys inside themes are now palette.*.
  • Control heights grew: size-control-sm 28 to 32, -md 36 to 40, -lg 44 to 48.
  • Shape: buttons, chips, lozenges, segmented controls and navigation items are pills. Fields, alerts, toasts and menus are 18px. Cards, dialogs and table wrappers are 28px. Radius xl is 18.
  • Cards, dialogs, menus, toasts and table wrappers lost their border. Use h-card--outlined for a line. h-card padding is 24 (was 16).
  • Type: Inter and JetBrains Mono become IBM Plex Sans and IBM Plex Mono. Display and headlines move to Bricolage Grotesque at weight 700. display is 44/48 (was 40/48), headline-lg is 34/40 (was 32/40).
  • Segmented control: the selected segment is a solid brand fill.
  • Toast: no colored left bar.

  • Five palettes: Polar (default), Aurora, Ember (its light theme is the sunrise one), Midnight (near black) and Nord (stock, opt in). Each has dark, light and increased contrast. Choose with data-palette.

  • Shape roles: shape-control, shape-field, shape-card, shape-hero, shape-data, and radius 3xl.
  • Two kinds of motion. Productive: duration-productive 160ms with ease-productive (from IBM Carbon's productive curve), for work. Expressive: duration-expressive 480ms with ease-spring, for wins and arrivals. Also duration-micro 70ms, ease-productive-enter, ease-productive-exit, ease-expressive.

  • Optional behavior. js/hali.js, no dependencies, opt in through data attributes. Gives tabs (arrow, Home and End keys), dropdown menus (arrow keys, Escape, focus return), dialog open and close, chips, segmented controls, sortable tables and a Hali.toast() helper.
  • Icons. 48 line icons on a 24px grid in icons/hali-icons.svg, and the Hali mark.
  • Accessibility. Visible focus ring at 3:1 or better on every surface, 44px targets on coarse pointers, reduced motion handling, forced colors support, prefers-contrast: more support and a manual data-contrast="more" switch.
  • Documentation. A single page reference site with foundations, components, patterns, content guidelines and resources, built by scripts/build_site.py.
  • Project. README, versioning policy, architecture and accessibility notes, contributing guide, issue and pull request templates, and a CI workflow that rebuilds tokens and fails on any contrast or version mismatch.

Known limitations

  • No date picker, combobox, tree view, toast manager or chart components yet. Their absence is deliberate for 1.0 because each needs behavior that CSS alone cannot provide.
  • Components are CSS first. Anything beyond what the optional js/hali.js provides, such as focus management inside custom widgets, is your application's job.
  • Inter and JetBrains Mono are named in the font stacks but are not bundled. Without them the system fonts are used.

Roadmap and contributing

What is next, and how to help.

These are directions, not promises. Each would arrive in a minor release.

  • Date picker and calendar. Needs careful keyboard and screen reader work, so it waits for its own release.
  • Combobox and multi select. The most requested missing input.
  • Tree view and stepper.
  • Chart components. The data visualization palette is ready. The components are not.
  • Density modes. Compact and comfortable variants of control sizes and table rows.
  • A Figma library generated from the same tokens.

Contributing

Propose a component with a short issue that answers four questions: what job does it do that nothing does today, which native element does it build on, what states does it have, and how does it behave at 320px, with a keyboard, and with a screen reader. Every pull request runs the build, which fails on any contrast miss or version mismatch. See CONTRIBUTING.md.
